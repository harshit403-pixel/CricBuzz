# Contribution Guide

## How Team Members Should Contribute

- Keep changes small and focused
- Do not touch unrelated files
- Use meaningful commit messages
- Test your work before raising a Pull Request
- Add a clear PR title and description
- For UI work, add screenshots if possible
- For backend work, mention how the API was tested if applicable
- Respect work already done by other team members
- Communicate before changing shared files
- Ask questions when requirements are unclear

## Good Team Habits

- Read the related files before making changes
- Avoid mixing multiple unrelated tasks in one branch or PR
- Share blockers early instead of waiting too long
- Review your own work before asking others to review it

## Collaboration Reminder

The goal is to help the team move smoothly without unnecessary confusion or conflicts. This guide is only an initial draft and can be updated after mentor instructions, team discussion, and official task assignments.
